# 07 输入候选格式约定（上游 06 → 本阶段）

> 目的：约定阶段 07「上下文组装器」的**输入契约**，使其与 06 检索流水线输出无缝对接，
> 同时保持对“裸 dict / JSON”输入的宽松兼容（便于离线样例与单测）。

## 1. 数据来源

阶段 07 的输入是**一组候选文档块**，来自 06 检索流水线：

```python
# 06 检索系统开发第二部分
from pipeline import RetrievalPipeline

pipe = RetrievalPipeline.from_mode("sample")   # 或 "full"
result = pipe.run("metformin cardiovascular effects")

candidates = result["reranked"]                 # 首选：重排后的候选列表
# 若 skip_rerank=True，则退化为 result["retrieval"]["fused"]
```

- **首选输入**：`result["reranked"]`（已做融合 + 多准则重排，含 `final_score`）。
- **退化输入**：`result["retrieval"]["fused"]`（仅融合，未重排，含 `fusion_score`）。
- **离线输入**：`06 .../outputs/samples/pipeline_eval.json` 的 `queries[i]["reranked"]`，
  可直接读 JSON 作为样例，无需联机检索。

## 2. 单个候选的字段（06 reranked item）

06 的候选为 `dict`，关键字段如下（07 只依赖标注为 **必需** 的字段，其余进 `metadata`）：

| 字段 | 类型 | 必需 | 说明 |
|------|------|:----:|------|
| `chunk_id` | str | ✅ | 块唯一 ID（如 `PMC520826` 或 `PMC524376_chunk0`） |
| `text` | str | ✅ | 块正文（title + abstract，组装上下文的内容来源） |
| `doc_id` | str | ✅ | 文档 ID（多样化 / 同源降权依据） |
| `source_title` | str | ➖ | 文献标题（多样化备用键、引用展示） |
| `source` | str | ➖ | 来源通道：`vector` / `keyword` / `fused` |
| `final_score` | float | ➖ | 重排最终分（**reranked 输入时**作为 `relevance_score`） |
| `fusion_score` | float | ➖ | 融合分（**fused 退化输入时**作为 `relevance_score`） |
| `relevance_score` | float | ➖ | 06 重排给出的相关性分（rerank 子项） |
| `recency_score` / `authority_score` | float | ➖ | 重排子项，留作 metadata |
| `vector_score` / `bm25_score` | float\|null | ➖ | 单路原始分 |
| `vector_rank` / `bm25_rank` | int\|null | ➖ | 单路排名 |
| `rank` | int | ➖ | 候选在列表中的名次 |
| `chunk_index` / `total_chunks` | int | ➖ | 块在原文中的位置 |
| `token_count` | int | ➖ | 06 估算的块 token 数（可复用/校验） |
| `strategy` | str | ➖ | 分块策略：`single` / `sliding_window` |
| `pub_year` | int\|null | ➖ | 出版年（回查自 slim 元数据） |
| `journal` | str\|null | ➖ | 期刊名 |
| `criteria_weights` / `rerank_explain` | dict | ➖ | 重排权重与解释，留作 metadata |

## 3. → `DocumentChunk` 字段映射（阶段 1 落地）

任务书定义的 `DocumentChunk`：`text / metadata / relevance_score / source / chunk_id`。
阶段 07 的转换约定（阶段 1 在 `models.py` / `context_assembler.py` 实现）：

| `DocumentChunk` | 取值规则 |
|-----------------|----------|
| `chunk_id` | 候选 `chunk_id`（缺失时回退 `doc_id`，再缺失则生成序号 ID） |
| `text` | 候选 `text` |
| `relevance_score` | 优先 `final_score` → 否则 `fusion_score` → 否则 `relevance_score` → 否则 `score` → 否则 `0.0` |
| `source` | 优先 `source_title` → 否则 `doc_id` → 否则 `source`（通道名） |
| `metadata` | 其余全部字段（`doc_id`, `source_title`, `pub_year`, `journal`, `strategy`, `token_count`, `chunk_index`, `total_chunks`, 各类 score/rank, `rerank_explain` 等）整体收纳 |

> 说明：`source` 用于“多样化 / 同源降权”。本约定以 `source_title`（同一篇文献）为主键；
> `doc_id` 始终保留在 `metadata` 内供去重 / 同源判断。

## 4. 宽松兼容约定

为便于单测与离线样例，组装器对输入做**容错**：

- 输入可为 `list[dict]`（06 候选）或 `list[DocumentChunk]`；混合也可。
- 缺失可选字段不报错，按第 3 节回退规则取默认值。
- `text` 为空或非字符串的候选在转换阶段被跳过（记入 metadata 统计）。

## 5. 输出契约（阶段 2 产出，提前登记）

`ContextAssembler.assemble(...)` 返回：

```python
{
    "context_text": str,                  # 拼好的上下文（已截断到 token 上限、句末边界）
    "metadata": {
        "total_chunks_retrieved": int,    # 输入候选数
        "unique_chunks_after_dedup": int, # Jaccard 去重后数量
        "chunks_selected": int,           # 最终入选数量
        "estimated_tokens": int,          # 估算 token 数
        "chunk_sources": dict,            # 来源分布统计
    },
    "selected_chunks": list[DocumentChunk],
}
```
