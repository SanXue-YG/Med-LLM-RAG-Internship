## 1. 概述

本阶段在 05/06/07 已完成工作的基础上，补齐 RAG 链路的**生成执行层**：

- **05**：查询理解与增强 → `EnhancedQuery`
- **06**：多路检索 + 融合 + 重排 → `reranked`
- **07**：上下文组装 + 医学 Prompt 模板 → `context_text` + `PROMPT_STAGES`
- **08（本阶段）**：Ollama 调用 + 多步生成 + 后处理 → 面向用户的 `answer` + `sources` + 指标

### 1.1 端到端数据流

```text
用户 query
    ↓ 06 RetrievalPipeline（本阶段评测使用离线 pipeline_eval.json 模拟）
    ↓ 07 ContextAssembler → context_text + selected_chunks
    ↓ 07 PROMPT_STAGES 四阶段 Prompt
    ↓ 08 LLMGenerator（Ollama /api/chat）
    ↓ 08 postprocess（引用 + Sources + 免责声明）
result { query, answer, sources, generation_metrics, intermediate_results, timestamp }
```

### 1.2 验证范围说明

| 项 | 本阶段 notebook / CLI 验证 | 说明 |
|----|---------------------------|------|
| 检索输入 | 06 离线样例 `pipeline_eval.json` | 与在线 `RetrievalPipeline.run()` 结构一致，便于复现 |
| 向量库规模 | 样本库 reranked（每条 query 5 条候选） | 非 610 万全量在线检索 |
| LLM | 本机 Ollama `deepseek-r1:7b` | 真实本地推理，非 mock |

> 结论：**生成链路已在样本检索结果上验证通过**；若切换生产全量检索，应改用 `RetrievalPipeline.from_mode("full")` 并保持 08 流水线接口不变。

## 7. 已知限制与后续建议

1. **证据评估 ID 对齐**：模型偶发返回 `"1"`/`"2"` 而非 `PMCxxxxx`；当前按 chunk 列表索引降级处理，后续可增强 id 映射与校验。
2. **评测检索为离线样例**：与真实在线 `mode="full"` 检索质量可能存在差异，上线前应复跑全量检索 + 08 流水线。
3. **可选阶段耗时**：完整路径（eval+review）约为最小路径 1.5–2 倍耗时，生产环境可提供 `skip_*` 开关按场景切换。
4. **LangChain 封装**：本阶段未做，可作为下一阶段工程化工作。
