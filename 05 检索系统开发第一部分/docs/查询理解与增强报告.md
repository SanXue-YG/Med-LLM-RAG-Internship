> **状态：已完成** — 查询增强模块 + 演示 notebook + 双库联调均已通过（2026-06-08）

## 1. 概述

本阶段在第四阶段 ChromaDB 向量索引就绪的基础上，实现 **查询理解与增强** 模块：将用户自然语言查询清洗、识别医学实体、扩展缩写与同义词，生成供向量检索与后续关键词检索使用的多版本查询，并从查询文本中解析结构化过滤条件。

**本阶段边界**：仅交付「增强后的查询对象」及与 04 检索接口的联调验证；**不包含** 混合检索、重排序、LLM 生成答案（属后续 RAG 阶段）。

### 1.1 输入与输出

| 项目 | 说明 |
|------|------|
| **输入** | 用户自然语言查询（本阶段以 **英文** 为主；见 §2.2） |
| **核心输出** | `EnhancedQuery` 对象（见 §3.1） |
| **下游消费** | 04 `ChromaIndexBuilder.query(enhanced.vector_query, where_filter=enhanced.chroma_where())` |

### 1.2 上游依赖（第四阶段）

| 资源 | 路径 | 本阶段用途 |
|------|------|------------|
| 嵌入模型封装 | `04 .../src/embedder.py` → `DocumentEmbedder` | 查询端 BGE 指令与编码（与建库一致） |
| 索引查询接口 | `04 .../src/index_builder.py` → `ChromaIndexBuilder.query()` | smoke test 联调 |
| 验证样本向量库 | `04 .../data/chroma_db/` → `pmc_oa_comm_sample`（1,267 条） | 开发期快速联调 |
| 全量向量库 | `04 .../data/chroma_db_full/` → `pmc_oa_comm_full`（6,107,296 条） | 抽样 query 计时 |

### 1.3 处理流水线

```
用户自然语言查询
    ↓ 基础清洗（去首尾空白、合并连续空格）
    ↓ 医学实体识别（MEDICAL_PATTERNS：drug / disease）
    ↓ 缩写识别 + 静态同义词扩展（medical_synonyms.json）
    ↓ 生成多版本查询
        ├─ vector_query  → raw 文本，供 04 encode_queries() + Chroma 语义检索
        └─ keyword_query → 去停用词 + 实体 + 扩展词，供后续 BM25/关键词检索
    ↓ 提取 filters（strategy / year / journal 等，区分可执行性）
EnhancedQuery
    ↓ （联调）ChromaIndexBuilder.query(vector_query, where_filter=chroma_where())
参考文档候选列表（后续阶段再做融合与答案生成）
```

## 3. 模块设计

### 3.1 核心数据结构（`src/models.py`）

**`EnhancedQuery`** — 查询增强的统一输出：

| 字段 | 类型 | 说明 |
|------|------|------|
| `original` | str | 原始用户查询 |
| `cleaned` | str | 清洗后文本 |
| `entities` | list[`EntityMatch`] | 实体：`type`, `text`, `start`, `end` |
| `expanded_terms` | list[str] | 同义词 / 缩写全称扩展项 |
| `vector_query` | str | 供 BGE/Chroma 语义检索（raw，无指令前缀） |
| `keyword_query` | str | 供后续 BM25/关键词检索 |
| `filters` | list[`FilterItem`] | 结构化过滤条件 |
| `metadata` | dict | 调试信息（嵌入模型、语言检测等） |

辅助方法：

- `filters_dict()` → `{key: value}` 字典视图
- `chroma_where()` → 仅含 **`executable=True`** 的 filter，供 Chroma `where=` 使用
- `to_dict()` → JSON 序列化（notebook / 样例导出）

**`FilterItem`** — 每个 filter 含 `executable` 标志，区分「已解析」与「当前索引可执行」。

### 3.2 查询增强器（`src/query_enhancer.py`）

**`MedicalQueryEnhancer.process(query: str) -> EnhancedQuery`**

| 步骤 | 方法 | 说明 |
|------|------|------|
| 清洗 | `_clean()` | 去首尾空白；`\s+` → 单空格 |
| 语言检测 | CJK 正则 | 含中文 → `metadata.language=zh_detected`，不翻译 |
| 实体识别 | `extract_entities()` | 调用 `medical_patterns.py` |
| 同义词扩展 | `_expand_synonyms()` | 缩写表 + 术语表 + 实体触发 |
| 关键词查询 | `_build_keyword_query()` | 英文停用词过滤 + 实体 + 扩展词，去重保序 |
| 过滤解析 | `_extract_filters()` | strategy / year / journal（见 §3.4） |

### 3.3 BGE 向量查询与第四阶段衔接

| 项目 | 本阶段 | 第四阶段 |
|------|--------|----------|
| `vector_query` 内容 | **raw 清洗文本** | — |
| BGE 指令前缀 | **不写入** `vector_query` | `encode_queries()` 自动添加 |
| 指令措辞 | — | `Represent this sentence for searching relevant passages: ` |
| 嵌入模型 | metadata 标注 `BAAI/bge-small-en-v1.5` | 建库同一模型 |

联调调用链：

```python
enh = MedicalQueryEnhancer()
eq = enh.process("metformin cardiovascular effects")
results = builder.query(eq.vector_query, n_results=5, where_filter=eq.chroma_where())
# builder 内部 → embedder.encode_queries(eq.vector_query) → Chroma query
```

### 3.4 过滤条件解析与可执行性

第四阶段 Chroma metadata 字段：`doc_id`, `chunk_index`, `total_chunks`, `source_title`, `token_count`, `strategy`。**无 `pub_year`、无 `journal`**。

| filter key | 触发示例 | executable | 说明 |
|------------|----------|------------|------|
| `strategy=sliding_window` | `sliding window` / `sliding_window` | **true** | Chroma metadata 支持 |
| `strategy=single` | `single chunk` / `single block` | **true** | Chroma metadata 支持 |
| `year_gte` | `after 2015` / `since 2020` | **false** | 解析意图；索引无 pub_year |
| `year_lte` | `2010-2020` 区间 | **false** | 同上 |
| `year_relative_years` | `last 5 years` | **false** | 需结合当前年与 slim JSONL |
| `journal_hint` | `in Nature` / `from Lancet` | **false** | 索引无 journal 字段 |

`executable=False` 的 filter 仍写入 `EnhancedQuery.filters`，供后续 RAG 阶段检索后二次过滤；**不会**传入 `chroma_where()`。

### 3.5 静态资源

**`data/medical_synonyms.json`**

| 类别 | 数量 | 示例 |
|------|------|------|
| `abbreviations` | 10 组 | `mi` → myocardial infarction, heart attack |
| `terms` | 10 组 | `metformin` → biguanide antidiabetic |

**`src/medical_patterns.py` — `MEDICAL_PATTERNS`**

| 类型 | 匹配方式 | 示例词 |
|------|----------|--------|
| `drug` | `\b` 单词边界 | metformin, aspirin, insulin, …（10 种） |
| `disease` | `\b` 单词边界 | malaria, cardiovascular, diabetes, …（11 种） |

### 4.3 与第四阶段 Chroma 联调（notebook C3–C5，可选但已完成）

**统一 smoke query**：`metformin cardiovascular effects`（Top-5，各重复 3 次计时）

产物：`outputs/samples/chroma_smoke_compare.json`

| 库 | collection | 条数 | 完整 HNSW bin | 平均 query 耗时 | where_filter |
|----|------------|------|---------------|-----------------|--------------|
| 样本 `chroma_db` | `pmc_oa_comm_sample` | 1,267 | ✅ | **12.1 ms** | `strategy=sliding_window` |
| 全量 `chroma_db_full` | `pmc_oa_comm_full` | 6,107,296 | ❌ | **16.2 ms** | 无 |

**样本库 Top 命中（节选）**：PMC523838、PMC524363 等相关 chunks。

**全量库 Top 命中（节选）**：PMC12822947、PMC12823101 等 — 与 metformin / cardiovascular 主题一致。

**元数据过滤行为**：样本库 C3 传入 `where_filter={"strategy": "sliding_window"}` 时，Chroma 原生 `where=` 报错，04 `index_builder.query()` 自动 **over-fetch + Python post-filter**（与 04 阶段 §4.4 行为一致），检索仍正常返回结果。

**HNSW bin 粗对比说明**：两库规模差约 4800 倍，本次同 query 下全量仅比样本慢约 1.3×，**不能**单独归因于 bin 有无；该对比主要用于确认 05→04 路径在全量规模下可用。

## 9. 结论与后续规划

### 9.1 结论

1. **任务书本周产出已完成**：查询理解与增强模块代码、`EnhancedQuery` 结构化输出、静态词典与实体识别、向量/关键词双查询生成、过滤条件解析均已实现并测试通过。
2. **与第四阶段对齐**：向量检索使用同一 **`BAAI/bge-small-en-v1.5`**；BGE 指令前缀由 04 统一添加，`vector_query` 保持 raw 文本，避免与建库向量空间不一致。
3. **过滤策略务实**：`strategy` 可在当前 Chroma metadata 上执行；`year_*` / `journal` 仅解析意图并标注 `executable=false`，不重建 610 万条索引。
4. **联调路径已验证**：`enhanced.vector_query` → `ChromaIndexBuilder.query()` 在样本库（1,267 条）与全量库（6,107,296 条）上均可正常返回相关 PMC 文献片段。
5. **查询语言**：按老师确认 **优先英文**；中文检测已预留 metadata，翻译链留后续。
