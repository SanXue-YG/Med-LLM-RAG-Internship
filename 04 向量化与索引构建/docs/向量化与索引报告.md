## 1. 概述

本阶段将第三阶段输出的文本块数据集（`oa_comm_chunks.jsonl`）通过 BGE 嵌入模型向量化，写入 ChromaDB 持久化索引，并完成基础统计、相似性检索、边界情况与元数据过滤等质量验证。

### 1.1 输入数据（来自第三阶段）

| 数据集 | 路径 | chunk 数 |
|--------|------|----------|
| 验证样本 | `data/processed/chunks_sample.jsonl` | **1,267** |
| 全量 | `data/processed/oa_comm_chunks.jsonl`（同步自 E:） | **6,107,296** |

- **检索单元**：title + abstract（与阶段 3 一致）
- **chunk 字段**：`chunk_id, text, doc_id, chunk_index, total_chunks, source_title, token_count, strategy`
- **唯一 id**：`chunk_id`（即 `doc_id` 或 `doc_id_chunk{i}`）

### 1.2 向量库配置

| 配置项 | 值 |
|--------|-----|
| 向量数据库 | ChromaDB 1.5.x（`PersistentClient`） |
| 相似度度量 | 余弦（`hnsw:space=cosine`） |
| 验证样本 collection | `pmc_oa_comm_sample` |
| 全量 collection | `pmc_oa_comm_full` |
| 入库方式 | 分批编码 + `collection.add`，断点续传（`*.progress.json`） |

### 1.3 嵌入模型（本阶段唯一选用）

| 项目 | 值 |
|------|-----|
| **模型名称** | **`BAAI/bge-small-en-v1.5`** |
| **HuggingFace ID** | 同上（代码默认值见 `src/embedder.py`） |
| **向量维度** | **384** |
| **文档端** | `encode_documents()` — **不加**指令前缀 |
| **查询端** | `encode_queries()` — 自动加前缀 `Represent this sentence for searching relevant passages: ` |
| **归一化** | L2 归一化后写入 Chroma（配合 cosine） |
| **加载方式** | `transformers.AutoModel` + mean pooling（不经 `sentence_transformers`） |

> **模型选择说明**：任务书列出的 BGE / OpenAI 等候选中，按本机设备性能**选定单一模型即可，无需多模型对比**。本阶段选用 `bge-small-en-v1.5`：610 万规模下存储与算力可接受，且英文检索效果优于 all-MiniLM；后续 RAG 须与建库使用**同一模型**。

## 2. 嵌入模型选择依据

### 2.1 候选与决策

| 模型 | 维度 | 本阶段是否采用 | 说明 |
|------|------|----------------|------|
| **`BAAI/bge-small-en-v1.5`** | 384 | **✅ 采用** | 轻量、610 万向量约 9 GB 量级，RTX 4080 可支撑全量 GPU 嵌入 |
| `BAAI/bge-base-en-v1.5` | 768 | 未采用 | 向量存储与计算量约翻倍 |
| `BAAI/bge-large-en-v1.5` | 1024 | 未采用 | 显存与磁盘压力更高 |
| OpenAI `text-embedding-3-*` | 1536+ | 未采用 | 付费 API，与本地离线 RAG 目标不符 |
| ClinicalBERT 等 | — | 未采用 | 需额外微调，超出本阶段范围 |

### 2.2 与阶段 2/3 tokenizer 的关系

阶段 2/3 的 token 统计基于 `all-MiniLM-L6-v2`；BGE 使用独立 tokenizer，但 chunk 最大 token（512）仍在 BGE `max_length=512` 内，**无需重新分割**。

### 4.2 相似性检索验证

#### （1）自相似性：索引文本作查询

从 JSONL 取首条 chunk 的前 300 字符，经 `builder.query()` 检索 Top-3，检查 Top-1 是否为原 `chunk_id`。

| 数据集 | 结果 | 说明 |
|--------|------|------|
| 验证样本（1,267） | **Top-1 命中自身** ✅ | `query_validation_sample.json`: `"自相似性命中自身": true` |
| 全量（610 万） | Top-1 未命中自身 ⚠️ | `query_validation.json`: `"自相似性命中自身": false` |

**说明**：查询走 `encode_queries()`（带 BGE 指令），建库走 `encode_documents()`（无指令），用文档原文片段当查询时存在**建库/查询不对称**；在 610 万规模下，语义相近的其他 chunk 也可能排在原 chunk 之前。该测试主要用于确认检索链路可用；**语义相关性以自然语言查询测试为准**（见下表）。

#### （2）语义检索：自然语言医学问题

在验证样本上执行三条固定查询（notebook C4），Top 结果与查询主题一致：

| 查询 | Top 命中（节选） | 相关性 |
|------|------------------|--------|
| What is the role of gene regulation in malaria parasites? | PMC176545 *The Transcriptome of the Intraerythrocytic Developmental Cycle...*；PMC314464 *Cell-Passage Activity... Malarial Parasite* | ✅ 疟疾/寄生虫 |
| conservation of Asian elephants | PMC176546 *Asian Elephants Are Native to Borneo*；PMC449851 *Extinction Risk... Carnivores* | ✅ 亚洲象/保护 |
| circadian rhythm in Drosophila | PMC193604_chunk1/2 *Drosophila Free-Running Rhythms...* | ✅ 果蝇节律 |

全量库上使用相同查询语句，检索正常返回结果（无异常中断），Top 标题均为 PMC 文献片段；因全库覆盖范围远大于验证样本，Top 排序与样本库不同，属预期现象。**检索接口与嵌入模型在全量规模下工作正常**。

### 4.3 边界情况验证

| 场景 | 验证样本 | 全量 | 状态 |
|------|----------|------|------|
| 空查询 `""` | 返回 3 条，未报错 | 返回 3 条，未报错 | ✅ |
| 超长查询（`diabetes ` × 2000） | 返回 3 条，截断后未报错 | 返回 3 条，截断后未报错 | ✅ |

超长文本在 `DocumentEmbedder` 内按 `max_length=512` token 截断处理。

### 4.4 元数据过滤验证 *

过滤条件：`where_filter={"strategy": "sliding_window"}`，仅返回多块滑动窗口切分的 chunk。

| 数据集 | 结果 | 状态 |
|--------|------|------|
| 验证样本 | 返回 3 条，均为 `strategy=sliding_window` | ✅ |
| 全量 | Chroma 原生 `where=` 报错后，自动 **over-fetch + Python 过滤**；返回 3 条均为 `sliding_window` | ✅ |

全量库元数据过滤已在 `index_builder.query()` 中降级处理；`query_validation.json` 中 `"元数据过滤生效": true`。

## 9. 结论与后续规划

### 9.1 结论

1. **模型已明确标注**：本阶段全部向量与检索结果对应 **`BAAI/bge-small-en-v1.5`（384 维）**；代码模块注释与 `index_stats.json` 均已记录。
2. **全量建库完成**：6,107,296 条 chunk 向量化入库，数量与第三阶段输出一致。
3. **质量验证通过**：基础统计、语义检索（验证样本）、边界查询、元数据过滤均符合任务书要求；全量规模下查询链路稳定。
4. **数据就绪**：向量库可供后续 RAG 检索；chunk 全文已存于 Chroma `documents`，日常 RAG **无需**再读 JSONL/XML。

### 9.2 RAG 阶段使用说明

1. **挂载路径**：`D:\谷歌\04 向量化与索引构建\data\chroma_db_full\`（或 E: 备份副本）
2. **检索代码**：复用 `ChromaIndexBuilder` + `DocumentEmbedder`，查询务必走 `encode_queries()`
3. **勿换模型**：更换嵌入模型需对全库重新向量化
4. **元数据过滤**：全库规模下可能触发 post-filter 降级，行为已在 `index_builder.py` 封装

详细调用示例见项目根目录 `README.md` →「第四阶段完成总结 → RAG 调用向量库」。
