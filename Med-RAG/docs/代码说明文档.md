# Med-RAG 代码说明文档

> **本文职责**：目录结构、阶段对应、关键类 / API 入口。  
> 数据落盘与 sample/full 产品角色见 [`数据存储与导入参考.md`](数据存储与导入参考.md)。

## 1. 定位

`Med-RAG/` 是仓库打包产物：把阶段 05–12 的问答能力与 02–04 的入库能力收进**单一目录**，配套 React Demo，用于演示 API 与本地 RAG 流水线。

不重写算法；路径全部本地化为 `Med-RAG/data/`。

**检索模式 vs 入库模式（代码边界）**：

- `MED_RAG_RETRIEVAL_MODE` → `RagService` / `from_mode(...)` 读哪套索引（sample 或 full）。
- `backend/ingest` + `POST /api/v1/ingest/upload` → **一期硬编码写 sample**（与检索模式无关）。  
  因此 sample 更像「可交互用户态」；full 更像「预建库导入后只读问答」，当前 Demo **不能**上传更新全库。

## 4. HTTP API（Demo 常用）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/health` `/ready` | 存活 / 索引就绪 |
| POST | `/api/v1/qa` | 同步问答 |
| POST | `/api/v1/qa/stream` | 伪 SSE |
| POST/GET/DELETE/PATCH | `/api/v1/sessions` | 会话（文件持久化；支持 list `GET /sessions?q=`） |
| GET | `/api/v1/stats/*` | QA / index / health |
| GET | `/api/v1/documents` | 文献目录 |
| POST | `/api/v1/ingest/upload` | 上传语料；**始终更新 sample 索引**（非 full） |

OpenAPI：`http://127.0.0.1:8000/docs`

## 5. 前端

- Vite + React；布局：左历史 / 右对话；四卡片链到示例问答、Swagger、原理、流程图。
- 回形针 → 语料上传对话框 → `POST /api/v1/ingest/upload`（落盘 sample；即使服务已切 full）。
- 开发代理：`frontend/vite.config.ts` 把 `/api` 转到 `:8000`。
