## 1. 概述

Med-RAG 的全部运行时数据位于 `Med-RAG/data/`，不依赖仓库外阶段目录。检索侧通过环境变量选择 **sample** 或 **full** 两套索引；入库侧（一期 Demo）固定写入 sample。

| 模式 | 定位 | 能力边界 |
|------|------|----------|
| **sample**（默认） | 本机交互态：可空库启动、可增量加文献 | 回形针 / `POST /api/v1/ingest/upload` **始终写入 sample** |
| **full** | 预建语料导入态：线下建库后迁入本包 | 修改 `.env` 并放置资产后即可问答；**一期不能**经 Demo 上传更新全库 |

约束说明：

1. **检索模式**（读哪套索引）与 **入库 API**（写哪套索引）在一期相互解耦。  
2. 新上传的 XML / JSONL **不论当前检索模式为何**，均写入 sample（`raw_uploads` → `chunks_sample` / `chroma_db` / `documents_sample`）。  
3. 在 full 模式下上传时，新文献不会进入 full 的 `/qa` 检索结果；验证增量更新应使用 sample，或上传后切回 sample。  
4. 全量语料增补需在 Dataset 侧建库 / 按「未来优化」补丁流程处理，或后续扩展 `ingest(mode=full)`（尚未实现）。

## 2. sample 与 full 的技术差异

阶段 **02–04**（解析 → 切块 → 嵌入建库）决定两套语料的**规模与工程成本**；阶段 **05–10** 的查询与生成逻辑基本共用，由 `from_mode("sample"|"full")` 与 `MED_RAG_RETRIEVAL_MODE` 切换路径与 collection 名称，而非维护两套算法。

| 环节 | sample | full | 说明 |
|------|--------|------|------|
| 02–04 建库 | 约 1k 篇 / 1,267 chunks | 约 455 万篇 / 610 万 chunks | 脚本同源，主要差在数据量与算力 |
| 05–10 问答 | 同一套 enhancer / 检索 / 生成 / 约束 | 同上 | 几乎无代码分叉 |
| BM25 | 无离线索引；查询时从 `chunks_sample.jsonl` **内存构建** | 读取 `bm25/bm25_full/` **分片离线索引** | 同一入口，`resolve_bm25_cache_dir` 分支 |
| Chroma | `chroma/chroma_db` · `pmc_oa_comm_sample` | `chroma/chroma_db_full` · `pmc_oa_comm_full` | 路径与集合名不同 |
| 文档目录 API | `documents/sample/*.sqlite` | `documents/full/*.sqlite` | 由 `MED_RAG_DOCUMENTS_MODE` 选择 |

要点：问答侧差异主要在于**指向哪套已建好的索引**；索引是否存在取决于 02–04（及 full 侧的 BM25 / documents 构建）是否已完成并迁入 `data/`。

## 3. 切换 full 模式

问答链路**无需修改业务代码**，按下列步骤即可：

1. 将 full 资产放入 `Med-RAG/data/`（见第 6 节）。  
2. 在 `Med-RAG/.env` 中设置：

```env
MED_RAG_RETRIEVAL_MODE=full
MED_RAG_DOCUMENTS_MODE=full
```

3. 重启 API：

```powershell
python backend/scripts/run_api.py --no-reload
```

资产缺失时，`/ready` 与 `/qa` 会报告索引未就绪，**不会**静默回退到 sample。

前端回形针与 `POST /api/v1/ingest/upload` 仍固定写入 sample（见第 5 节）。切换 full 只改变问答读取路径，不会使上传进入全库。

## 4. `data/` 目录布局

```text
Med-RAG/data/
├── chroma/
│   ├── chroma_db/              # sample 向量库（预置或 ingest 写入）
│   └── chroma_db_full/         # full 向量库（迁入，约 70GB）
├── bm25/
│   └── bm25_full/              # 仅 full 使用（sample 不读此目录）
├── documents/
│   ├── sample/documents_sample.sqlite
│   └── full/documents_full.sqlite
├── processed/
│   ├── chunks_sample.jsonl     # sample BM25 语料；亦可用于重建 chroma
│   ├── oa_comm_chunks.jsonl    # full 重建原料（约 9GB）
│   └── oa_comm_slim.jsonl      # 可选；重建 documents / 元数据回查（约 9GB）
├── raw_uploads/                # 上传原始 XML / JSONL
├── lexicons/medical_synonyms.json
├── chat/                       # 会话持久化（与 sample/full 无关）
└── logs/
```

### 4.1 sample 模式运行时读取

| 用途 | 路径 | 说明 |
|------|------|------|
| 向量检索 | `data/chroma/chroma_db/` · `pmc_oa_comm_sample` | 预建持久化库，或由 ingest `add` 增量写入 |
| BM25 | `data/processed/chunks_sample.jsonl` | 查询时在进程内构建；**不读** `bm25/` |
| 文档 API / 篇级元数据 | `data/documents/sample/documents_sample.sqlite` | 服务 `/documents` 等 |
| 同义词 | `data/lexicons/medical_synonyms.json` | 查询增强 |
| slim 回查 | `data/processed/oa_comm_slim.jsonl` | 可选；缺失时 recency / authority 相关能力退化 |

补充说明：

- Chroma sample 一般来自阶段 04 的预建目录，或 Demo ingest 的增量写入；启动时直接打开已有库。  
- BM25 sample 在查询时从 `chunks_sample.jsonl` 现建。  
- `documents` sqlite 不能替代 Chroma，二者职责不同。

### 4.2 full 模式运行时读取

| 用途 | 路径 | 说明 |
|------|------|------|
| 向量检索 | `data/chroma/chroma_db_full/` · `pmc_oa_comm_full` | 运行时必需 |
| BM25 | `data/bm25/bm25_full/`（分片 + manifest） | 强烈建议齐全 |
| chunks 全量 JSONL | `data/processed/oa_comm_chunks.jsonl` | 用于重建；已有 chroma + bm25 时可不挂问答热路径 |
| 文档 API | `data/documents/full/documents_full.sqlite` | `MED_RAG_DOCUMENTS_MODE=full` |
| slim | `data/processed/oa_comm_slim.jsonl` | 重建或元数据回查时可选 |

sample / full 的区分不仅体现在 `documents/`：`chroma/`、`processed/`、`bm25/` 均有对应资产。`documents` 仅因目录结构更直观而更常被单独提及。

## 5. 语料上传与落盘

上传原件保存位置：

```text
data/raw_uploads/<timestamp>_<id>_<filename>
```

该目录随包提供（默认可为空，保留 `.gitkeep`）。

一期 ingest **固定写入 sample 三件套**，与 `MED_RAG_RETRIEVAL_MODE` 无关：

```text
parse / chunk
  → append  data/processed/chunks_sample.jsonl
  → Chroma add → data/chroma/chroma_db  (collection pmc_oa_comm_sample)
  → upsert   data/documents/sample/documents_sample.sqlite
```

行为约定：

- 不写入 `documents/full`，也不新建第三套库；增量合并进既有 sample 索引。  
- 即便当前为 full 检索模式，上传结果仍只进入 sample。  
- 全量增补需迁入或补丁 full 索引，或待后续实现 `ingest(mode=full)`。

## 6. 从 Dataset / Google Drive 引入资产

### 6.0 约定共享位置

仓库根 `Dataset/` 为本地主路径；对外备份与共享约定使用下列 Google Drive 文件夹（内容与 `Dataset/` 对齐，上传可能仍在进行中，以 Drive 实际文件为准）：

**[Google-Med-RAG / Dataset](https://drive.google.com/drive/folders/1uK-2nbpOAWH61pWWrArpR8fdUzUihZ7H?usp=sharing)**

```text
https://drive.google.com/drive/folders/1uK-2nbpOAWH61pWWrArpR8fdUzUihZ7H?usp=sharing
```

从 Drive 下载后，按下方清单解压或复制到本机 `Dataset/`，再按需拷贝进 `Med-RAG/data/`。

### 6.1 full 问答最小运行集

优先迁移下列资产，即可在放置后将 `.env` 设为 full 并重启服务：

| 源（仓库 `Dataset/`） | 目标（`Med-RAG/data/`） | 体量量级 |
|----------------------|-------------------------|----------|
| `chroma/chroma_db_full/` | `chroma/chroma_db_full/` | 约 66–71 GB |
| `bm25/bm25_full/` | `bm25/bm25_full/` | 约 15 GB |
| `documents/full/documents_full.sqlite`（同目录 manifest 可选） | `documents/full/` | 约 11.5 GB |

### 6.2 重建原料（建议备份，非日常问答必需）

| 源 | 目标 | 用途 |
|----|------|------|
| `processed/oa_comm_chunks.jsonl` | `processed/` | 重建 BM25 / Chroma |
| `processed/oa_comm_slim.jsonl` | `processed/` | 重建 documents / 元数据 |
| `processed/chunks_sample.jsonl` | `processed/` | sample 重建 |
| `chroma/chroma_db/` | `chroma/chroma_db/` | sample 联调 |
| `documents/sample/` | `documents/sample/` | sample 文档 API |

### 6.3 日常问答可不挂载的内容

- 已具备 chroma_full、bm25_full、documents_full 时，日常 `/qa` 可不挂载全量 slim / chunks JSONL。  
- Ollama 模型与 HuggingFace 嵌入 / reranker 缓存通常不在 `Dataset/` 内，需本机另行准备。

### 6.4 Google Drive 目录约定

共享根目录见 [§6.0](#60-约定共享位置)。文件夹内建议（或已有）按 `Dataset/` 同源布局存放，例如：

```text
Google Drive/Google-Med-RAG/
└── Dataset/                 # 与仓库 Dataset/ 对应
    ├── chroma/
    ├── bm25/
    ├── documents/
    └── processed/
```

若另行整理备份包，也可采用：

```text
runtime-full/          # §6.1 三件套（可分卷压缩）
runtime-sample/        # chroma_db + chunks_sample + documents_sample
rebuild-raw/           # slim + chunks 全量 JSONL
MANIFEST.md            # 路径、体积、校验（count / sha256）
```

## 7. 数据流图

### 7.1 sample 问答（默认）

```text
.env MED_RAG_RETRIEVAL_MODE=sample
        │
        ▼
POST /api/v1/qa
        │
        ▼
ConstrainedGenerationPipeline.from_mode("sample")
        │
        ├─► Chroma:  data/chroma/chroma_db  (pmc_oa_comm_sample)
        ├─► BM25:    chunks_sample.jsonl → 进程内 build
        ├─► (可选) slim / documents_sample 元数据
        └─► Ollama:  本机 deepseek-r1:7b
                │
                ▼
         answer + sources
```

### 7.2 full 问答

```text
放置 full 资产到 Med-RAG/data/
.env MED_RAG_RETRIEVAL_MODE=full
     MED_RAG_DOCUMENTS_MODE=full
重启 API
        │
        ▼
POST /api/v1/qa
        │
        ▼
from_mode("full")
        │
        ├─► Chroma:  data/chroma/chroma_db_full  (pmc_oa_comm_full)
        ├─► BM25:    data/bm25/bm25_full/  (分片离线)
        ├─► Documents API: documents/full/documents_full.sqlite
        └─► Ollama:  同上
```

### 7.3 语料上传 / 空库冷启动（一期仅 sample）

```text
UI 📎 / POST /api/v1/ingest/upload
        │
        ▼
data/raw_uploads/<file>
        │
        ▼
parse XML 或读 JSONL → chunk
        │
        ├─► append  processed/chunks_sample.jsonl
        ├─► add     chroma/chroma_db (sample collection)
        └─► upsert  documents/sample/documents_sample.sqlite
        │
        ▼
reset RagService 单例 → 后续 /qa（在 sample 模式下）使用更新后的索引
```

### 7.4 阶段生产与 Demo 消费

```text
[02 解析] XML/语料 ──► slim JSONL
[03 切块]            ──► chunks JSONL     ⎫
[04 嵌入]            ──► Chroma 目录       ⎬  sample 规模小、full 规模大
[09 BM25]            ──► bm25_full（仅全量）⎭
[12 documents]       ──► documents_*.sqlite
        │
        │  复制 / 挂载至 Med-RAG/data/
        ▼
[05–10 + FastAPI]  from_mode(mode) 选择路径 ──► 问答
```

## 8. 摘要

| 主题 | 说明 |
|------|------|
| 代码差异 | 建库规模集中在 02–04；问答代码共用，按模式切换路径 |
| 切换 full | 放置资产、修改 `.env`、重启进程；无需改业务代码 |
| sample 运行时 | `chroma_db` + `chunks_sample.jsonl` + `documents_sample.sqlite` |
| 目录区分 | chroma / processed / bm25 / documents 均区分或对应 sample 与 full |
| Chroma 来源 | 预建或 ingest 增量写入；非由 documents sqlite 运行时现建 |
| 上传落盘 | 一期仅 sample；原件在 `raw_uploads/` |
| Drive 备份优先 | full：`chroma_db_full` + `bm25_full` + `documents_full.sqlite`；共享位置见 §6.0 |
