# Med-RAG 部署文档

> **本文职责**：环境依赖、启动步骤、如何把服务切到 full。  
> 数据路径细节与 Drive 迁移清单见 [`数据存储与导入参考.md`](数据存储与导入参考.md)。

## 0. sample / full 怎么选（运维视角）

| 模式 | 适用场景 | 操作要点 |
|------|----------|----------|
| **sample**（默认） | 本机 Demo、空库冷启动、回形针增量更新 | 保持 `MED_RAG_RETRIEVAL_MODE=sample` |
| **full** | 已有全量索引、只做大规模问答演示 | 迁入资产 → 改 `.env` → **重启**；**不要用回形针期望更新全库** |

**注意**：一期 `POST /api/v1/ingest/upload`（前端回形针）**无论当前检索模式为何，都只写入 sample 索引**。若已切 full 仍上传，新文献不会进入 full 检索结果；验证上传请用 sample 模式。

## 1. 环境要求

| 项 | 建议 |
|----|------|
| OS | Windows 10/11（本包在此验证） |
| Python | 3.11.x，Conda 环境 `med-rag-verify`（与仓库 01–12 共用） |
| Node.js | 18+（前端） |
| Ollama | 本机 `http://127.0.0.1:11434`，模型 `deepseek-r1:7b` |
| 磁盘 | sample 索引约数十 MB；full 需另备 70GB+ 外置数据 |

```powershell
conda activate med-rag-verify
cd Med-RAG
pip install -r requirements.txt
copy .env.example .env
```

若缺少上传依赖：`pip install python-multipart python-dotenv`

## 2. 数据准备

### 方式 A：复制已有样本资产

```powershell
Copy-Item ..\Dataset\processed\chunks_sample.jsonl .\data\processed\ -Force
Copy-Item -Recurse ..\Dataset\chroma\chroma_db .\data\chroma\chroma_db -Force
Copy-Item ..\Dataset\documents\sample\documents_sample.sqlite .\data\documents\sample\ -Force
Copy-Item ..\Dataset\..\Med-RAG\data\lexicons\medical_synonyms.json .\data\lexicons\ -Force
```

（同义词表已随包提供在 `data/lexicons/` 与 `backend/rag/stage05/data/`。）

### 方式 B：空库启动后上传（仅更新 sample）

1. 确认 `.env` 中 `MED_RAG_RETRIEVAL_MODE=sample`（推荐）  
2. 启动 API + 前端  
3. 点击输入框旁回形针，上传 PMC `.xml` 或 slim/chunks `.jsonl`  
4. 服务写入 **sample** 侧：`raw_uploads/` → `chunks_sample.jsonl` / `chroma/chroma_db` / `documents/sample/`，并重置 pipeline 单例  

### 全量（可选：预建导入，非 Demo 上传）

全量更接近「其它流程建好库 → 拷进本包只读使用」：将 `chroma_db_full` / `bm25_full` / `documents_full.sqlite` 放入对应 `data/` 子目录，`.env` 中：

```
MED_RAG_RETRIEVAL_MODE=full
MED_RAG_DOCUMENTS_MODE=full
```

然后**重启** API 进程。一期 Demo **无法**通过回形针把新 XML 写入 full 索引。

> 详细对照、回形针落盘位置、从 `Dataset/` / [Google Drive 共享 Dataset](https://drive.google.com/drive/folders/1uK-2nbpOAWH61pWWrArpR8fdUzUihZ7H?usp=sharing) 迁移清单与流程图：  
> [`数据存储与导入参考.md`](数据存储与导入参考.md)。

## 3. 启动

```powershell
# 终端 1 — API
conda activate med-rag-verify
cd Med-RAG
python backend/scripts/run_api.py --no-reload

# 终端 2 — UI
cd Med-RAG\frontend
npm install
npm run dev
```

- API：`http://127.0.0.1:8000/docs`  
- UI：`http://127.0.0.1:5173`  
- 健康：`GET /health?check_ollama=true` · `GET /ready`

## 4. 环境变量（摘要）

见 [`.env.example`](../.env.example)。要点：

- `MED_RAG_RETRIEVAL_MODE`：`sample`（默认，可交互更新）/ `full`（预建导入）  
- `MED_RAG_DOCUMENTS_MODE`：文档 API 读 sample 还是 full sqlite（建议与检索模式一致）  
- `MED_RAG_CHAT_DIR`：默认 `data/chat`  
- `MED_RAG_CORS_ORIGINS`：Vite 源  
- `OLLAMA_*`：本地 LLM  

检索模式与上传落盘**解耦**：改 `RETRIEVAL_MODE` 只影响 `/qa` 读哪套索引；上传 API 仍写 sample。

生成的 zip **不含** `data/chroma`、全量索引、`node_modules`；附带数据放置说明。

## 7. Docker 评估结论（一期）

| 组件 | 容器化建议 |
|------|------------|
| FastAPI + 前端静态资源 | 可行 |
| Ollama + GPU/大模型 | **外挂本机进程**更稳妥 |
| Chroma/BM25 全量 | **volume 挂载**，勿打进镜像层 |

一期正式交付：**本地双进程 + 本文档 + zip**。若后续需要，可在 `scripts/docker/` 增加 compose 草稿（API 容器 + 数据 volume + 外部 Ollama URL），不作为当前阻塞项。
