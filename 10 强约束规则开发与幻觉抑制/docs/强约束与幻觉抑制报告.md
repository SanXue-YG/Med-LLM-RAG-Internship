## 1. 概述

本阶段在 08 端到端生成与 09 外侧评估之上，补齐 RAG 链路的**安全约束与幻觉抑制层**：

| 阶段 | 角色 |
|------|------|
| **08** | 生成执行 → `answer` + `sources` |
| **09** | 外侧阅卷（ROUGE / 软幻觉）+ 缓存 + 批量 |
| **10（本阶段）** | 考前纪律 + 交卷安检 + 纪律抽考 → `constraint_checks` + 对抗指标 |

### 1.1 端到端数据流

```text
query
  ↓ 06/08 检索 + 07 组装（context 原无编号）
  ↓ CitationGuard.assign_labels → context 带 [1]…[k]
  ↓ ConstraintPromptBundle.append_to(各步 system)（保留 07，追加约束）
  ↓ 08 多步 LLM 生成
  ↓ CitationGuard → FormatChecker
     ├─ fail → retry（max_retries）/ repair / soft_patch
  ↓ ConstrainedGenerationResult
  ↓ （阶段 5）adversarial_cases → 指标汇总 → adversarial_eval_report_full.json
```

### 1.2 验证范围说明

| 维度 | 本阶段实际使用 | 说明 |
|------|----------------|------|
| 全量资源自检 | C0.5：chroma / chunks / BM25 / slim **ready** | 与 09 全量路径对齐；不每次冷启检索做单测 |
| 单元测试 | pytest **43 passed** | fixture 假数据，不依赖 Ollama |

## 5. 关键设计决策（落地口径）

| 决策 | 取值 | 理由 |
|------|------|------|
| 约束注入 | `append_to` | 不覆盖 07 各阶段 system |
| context 编号 | 组装后 `assign_labels` | 对齐 08 `format_sources.index` |
| 格式章节 | 别名表 | 兼容 `**Answer:**` / `Sources:` |
| 拒答 × 格式 | `boundary_hit` 豁免三节 | 避免正确拒答被误杀 |
| journal/year | 默认 `relaxed` | 08 sources 常无此字段 |
| 缺引用 | 默认 `warn` | MVP 硬失败只抓越界编号 |
| 验证策略 | 默认全量路径就绪 + 陷阱 fixture | 跳过样本 offline 主轨 |
| 重试 | 开发 `max_retries=1` | 控 Ollama 耗时 |

## 7. 边界与后续

1. **mock ≠ live**：正式结论需在 Ollama live 下重跑对抗样例。  
2. **禁止编造**无 NLI 事实核查；依赖 prompt + 启发式 + 人工抽检。  
3. **临时编号 `[n]`** 仅对单次问答内有效；长期回查用 `chunk_id` / `doc_id`（见笔记 Q4）。  
4. 下一阶段候选：LangChain_RAG 产品化封装；或把 10 护栏挂入 09 批跑入口。
